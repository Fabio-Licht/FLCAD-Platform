## ABI and format

`flcad_occ_brep_stream_version()` returns 1. `flcad_occ_brep_stream_v1` accepts
borrowed shape token, nonzero uint64 max_bytes, sink and result storage/size.
It reuses only the common sink/result C types from mesh streaming. Tessellation
parameters, triangle budget and STL layout are NOT BREP requirements.
`result.triangles` is reserved zero for this entrypoint; result.version is ABI 1.
Windows x64 sink/result layouts remain 24/288 bytes. A C translation unit calls
both version/entrypoint pairs. No existing symbol/signature is changed.

`BRepTools::Write(shape, ostream, true, true, VERSION_3)` explicitly selects
OCCT ASCII BREP topology format 3, including triangulations and their normals.
Header includes `CASCADE Topology V3`. Classic C++ locale is selected on the
stream; OCCT controls numeric precision (its native double representation writer).
This is ASCII, not STL float32 or an endian-dependent packed format. Version 3
is supported by the tested OCCT 8.0.1 reader; no compatibility promise is made
for older readers that do not understand V3. The legacy writer on this SDK uses
true,false,CURRENT (currently V3); the new writer additionally retains available
triangulation normals. No meshing, healing, conversion or shape mutation is
requested by the new API.

## Sink, lifetime and stream implementation

Callback is synchronous on the caller thread; NULL opaque context is allowed.
Byte spans/accepted pointer are valid only within the call. Caller keeps context,
callback and borrowed shape lease alive, excludes concurrent shape mutation and
shutdown, and provides valid nonoverlapping ABI storage. A live OCCT reference
pins the shape during serialization. No token is minted or ownership transferred.
No filesystem or Windows HANDLE is exposed or used.

A custom streambuf buffers at most 64,000 bytes. It implements xsputn, overflow
and sync; no put area permits bypassing the checks. Large writes are copied in
bounded slices. It does not build a full BREP string. OCCT itself may allocate
shape tables during serialization: bounded output buffering is not a bound on
all OCCT memory. max_bytes limits serialized byte count, not runtime/shape size.
Checked `count <= limit-generated` precedes all increments; accepted totals cannot
exceed generated bytes. Counter-limit tests do not allocate an enormous BREP.

Every nonempty sync/full-buffer delivery calls the consumer. Code 0 + full count
continues. Short acceptance, even with code 0, is terminal and not retried. Nonzero
consumer code is preserved; -1 means cancellation. Valid partial acceptance is
added to bytes_accepted. Count greater than offered or exception from the callback
marks accepted_count_valid=0; bytes_accepted then contains only the previously
confirmed prefix, not an invented count of the current callback's effects.

Failure is sticky, so subsequent xsputn/overflow/sync cannot invoke the sink.
The ostream throws on failbit/badbit; outer catches preserve a previously recorded
consumer cause instead of replacing it with an iostream exception. OCCT, standard
and unknown exceptions are contained at the C boundary. Errors before any sink
call report zero confirmed bytes. Errors after confirmed bytes retain their count.
Messages are bounded/copy-only; consumer numeric codes are not truncated.

Finalization is explicit (`stream.flush()`), and may fail even after all bytes
were accepted. Only OK means complete. Destructors never flush or call the sink.
An unsuccessful prefix is never declared rolled back or durable; seal/commit is
the consumer's responsibility. No finish/abort callback or deletion is performed.
Cancellation is cooperative at callbacks; OCCT shape enumeration between writes
cannot be asynchronously interrupted by this ABI.

Thread-local RAII guard rejects nested BREP stream calls before byte production.
Nested rejection has a separate result; consumer decides whether to propagate it
to its outer stream. Recursive calls must use separate ABI storage. Reentry into
other mutation/shutdown APIs is forbidden by the borrowed-shape contract; this
API does not retrofit all legacy entrypoints with a guard.

## Equivalence and tests

Test fixtures include solid box, sphere, a compound of 100 transformed boxes,
a sphere with precomputed triangulations/normals, and shapes imported through
the productive flcad_occ_import_shape entrypoint. Streaming does not create files;
tests materialize its bytes in exclusive temporary fixtures only to exercise the
unchanged productive pathname reader. Legacy export/import is tested separately.

For each controlled fixture: stream -> productive restore -> stream -> productive
restore, then legacy export -> productive restore -> stream. Check topological
validity, shape kind, unique solid/shell/face/wire/edge/vertex counts, optimal bbox,
area, volume and centers of mass, with explicit finite checks and relative 1e-8
tolerance. First stream restore also checks stored triangulation positions/counts
and normals (1e-7 tolerance). A subsequent copy/transform checks continued kernel
usability. These are fixture-specific equivalence checks, not proof that aggregate
measurements uniquely identify every possible shape. No misleading comparison of
process-local fingerprint across restored objects is used. Original fingerprint
is checked unchanged by serialization, and 20 serializations compare exact bytes
within the same SDK/process. No cross-version byte determinism is promised.

Failure matrix covers first/intermediate/last callback, consumer error, zero-code
partial write, invalid count, cancellation, three exception classes after partial
consumption, and partial write with nonzero consumer code (24 combinations).
Fifteen injected exceptions cover before serialization, buffer write, after first
successful callback, before final flush and after final flush. Hooks exist only
in the implementation-level test executable, never in the production DLL.
Tests also cover missing callback/context/version/storage/token, reentry, byte
limits, overflow/xsputn/sync failure, registry/sequence invariants, source validity,
no new filesystem entries, repeated serialization, and C ABI compatibility.
A separate smoke links the productive DLL and performs serialization, cancellation,
productive restoration, reserialization and owner-controlled destruction.

## Validation and limits

Validated on Windows x64, MSVC 14.51 / Visual Studio 18 2026, OCCT 8.0.1:

| Configuration | Build | CTest |
|---|---|---|
| Debug | passed | 7/7, 6.94 s |
| Release | passed | 7/7, 7.87 s |
| Release + AddressSanitizer | passed | 7/7, 33.74 s; no sanitizer diagnostic |

Five existing CTest executables (including the extended C ABI smoke) remain;
two BREP executables were added. Internal cases include 24 consumer-failure
combinations, 15 injected-exception combinations, 20 deterministic repetitions,
preflight/overflow/reentry checks and four geometric fixtures. Each fixture
undergoes two streamed restores and one legacy restore (12 productive imports);
the separate productive-DLL smoke adds its own restore of a 735-byte BREP.
Counts inside executables are not additional CTest tests.

Build commands use the existing `build/occ_mesh_stream` configuration with
`cmake --build ... --config Debug/Release`, then `ctest --test-dir ... -C
Debug/Release --output-on-failure`. ASan uses `build/occ_mesh_stream_asan`,
Release, `FLCAD_OCC_ADDRESS_SANITIZER=ON` and the MSVC Hostx64/x64 runtime on PATH.
Both new test targets are instrumented as well as the productive DLL. Logs are
ignored under `build/occ-brep-{debug,release,asan}.log` and the CTest Temporary
logs of those build directories. No build artifact is versioned.

Three independent read-only reviews covered ABI/streambuf, geometry/round-trip,
and ownership/failure/test quality. The finite-comparison finding was corrected;
triangulated-normal coverage and a nonidentity transform after reopen were added.
Final revalidation found no critical/high/medium findings. Low residual limit:
individual triangle indices are not compared explicitly; fixture topology,
triangulation positions/counts/normals and post-restore operations are checked.
clang-format dry-run and Git whitespace checks passed.

The OCCT SDK is prebuilt and not instrumented by our ASan build. Windows ASan is
not LeakSanitizer; repeated registry/sequence/owner checks and sanitizer execution
are not an exhaustive third-party heap-leak proof.

Both required native output paths now exist: STL for display and BREP for durable
shape state. Integration still requires FFI bindings, custody/leases, synchronous
sink delivery into staging, cancellation mapping, seal/promotion, documentary
commit, managed save/open and integrated tests. Productive restoration still uses
the legacy read-only pathname API; integration must maintain the required input
identity/confinement guarantees when invoking it. No claim of end-to-end 2B2A
approval is made, and no producer is migrated by this commit.
